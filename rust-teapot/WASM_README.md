# Utah Teapot - WebAssembly Version

The classic Utah Teapot rendered in a web browser using Rust and WebAssembly.

## Overview

This project ports the original Rust teapot renderer from native desktop to WebAssembly, allowing it to run directly in a web browser. The teapot model is embedded at compile time and rendered using kiss3d's WebGL backend.

## Files

- `src/lib.rs` - WASM entry point with embedded teapot model
- `src/main.rs` - Original native version (kept for reference)
- `www/index.html` - HTML host file for the browser
- `teapot.obj` - The Utah teapot model (embedded at compile time)

## Building

### Prerequisites

Install wasm-pack:
```bash
cargo install wasm-pack
```

Add the WASM target:
```bash
rustup target add wasm32-unknown-unknown
```

### Build for Web

```bash
wasm-pack build --target web
```

This creates a `pkg/` directory with the compiled WASM module and JavaScript bindings.

## Running

Serve the `www/` directory with any static file server:

```bash
cd www
python3 -m http.server 8000
```

Then open http://localhost:8000 in your browser.

## How It Works

1. **Embedded Model**: The `teapot.obj` file is embedded at compile time using Rust's `include_str!` macro
2. **Virtual Filesystem**: In WASM, the embedded data is written to a virtual filesystem path (`/teapot.obj`)
3. **kiss3d Rendering**: kiss3d handles all WebGL setup automatically in WASM mode
4. **Animation Loop**: The teapot rotates continuously using kiss3d's `State` trait and `render_loop`

## Browser Compatibility

Requires a modern browser with:
- WebAssembly support
- WebGL support

Tested on Chrome, Firefox, Safari, and Edge.

## Key Technical Details

### WASM Configuration
- `crate-type = ["cdylib", "rlib"]` in Cargo.toml enables both library and binary builds
- `wasm-bindgen` provides Rust/JavaScript interop
- `#[wasm_bindgen(start)]` marks the entry point

### Model Loading
Since WASM can't access the host filesystem, the teapot model is embedded at compile time:
```rust
const TEAPOT_OBJ_DATA: &str = include_str!("../teapot.obj");
```

In the WASM environment, this data is written to a virtual file that kiss3d can load.

### Render Loop
kiss3d uses a `State` trait pattern for the render loop:
```rust
impl State for TeapotState {
    fn step(&mut self, _window: &mut Window) {
        // Animation logic here
    }
}
```
